# 核心信条

## 1. 先守住成长故事

这个站点首先是给家人和朋友看的成长绘本。页面、动效和内容都应帮助访客看见楚然的故事，而不是展示工程复杂度。

## 2. 保持静态与轻量

站点不引入后端、数据库或账户体系。内容由仓库中的静态数据和资源维护，部署保持为零运维的静态站点。

## 3. 视觉服务于阅读

手绘感、动画和色彩是体验的一部分，但不能遮住照片、文字或导航。动效应是可回退的增强，静态内容始终可读。

## 4. 依赖要有明确职责

每个直接依赖都必须支撑现有的页面、构建、质量检查或维护流程。没有实际职责的依赖应移除；主版本升级应单独验证并留下记录。

## 5. 文件即内容入口

页面文件生成路由，页面组合组件、静态数据和资源。共享逻辑放在 composable 或 utils，避免把业务规则分散到多个页面。

## 6. 文档跟随事实

代码、配置和已验证的行为是当前事实。文档发生漂移时先回写文档；长期架构边界确需改变时，先记录设计决策。
